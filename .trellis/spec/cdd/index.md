# Concept Design Documents

全项目唯一有权定义 "这个东西叫什么" 的层: 术语 → 定义 → 代码规范命名.

## 文档清单

- terms.md — 术语与代码命名真源 (组件, 优选池, 缓存, ECH, ECS, 客户端等十组).

## 文档格式

本体文档登记于文档清单; 写作参照同目录 terms.md.template, 具体形式不做硬要求; 术语取词遵守本文取词五律, 概念抽取遵守本文概念抽取四律; 两时态词表必过. 平铺文件, 不建子目录. 与上游模板的本地分歧声明在本节, 上游模板保持原样以零冲突同步.

## 取词五律

1. 长期优先 — 钉长期维护最优解, 不迁就改名成本; 偏差记为待清理项, 代码向 spec 看齐.
2. 业界常见优先 — 生态惯例词直接沿用; 自造词与罕见缩写须有充分理由.
3. 语义自解释 — 名字即职责, 不依赖编号或映射表.
4. 一词一义 — 同一个词不跨域承担两种语义.
5. 正名唯一 — 一个概念域一个正名; 动作名, 句柄名分层合法, 映射钉在术语表.

## 概念抽取四律

prd 表述上升为术语条目的判据:

1. 多处引用 — prd 跨功能, 跨字段反复引用的词, 是稳定引用点, 入表.
2. 有独立行为面 — prd 为它专门写了规则, 异常或验收, 而非顺带提及, 入表.
3. 有漂移风险 — 存在多种叫法或易混词, 不钉名会漂移, 入表.
4. 同层对称 — 同层概念组要么都入要么都不入.

不入的三种情况: 生态惯例词 (如 markdown, 命令面板); 纯展示细节无命名分歧风险; 子结构无独立行为面 (留在父概念定义里).

粒度原则: 实例有独立的验收与独立的配置面才独立成条, 否则留在总括定义里列举.

## Pre-Development Checklist

- 写任何新命名前 (类型, 函数, 模块, 配置键): 先查本层术语表.
- 引入新概念: 同变更入表, 代码命名可暂空; 只在代码里命名而不入表, 或入表而不落码, 均视为未完成.
- 代码合入时: 回填对应术语的代码命名, 跑 `python3 .trellis/scripts/verify_spec.py`.
