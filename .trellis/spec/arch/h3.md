# h3

业务逻辑:
- 每来源整份覆盖其 verdict 报告, 上限 8 来源, 每份 64 主机; 过期惰性清理.
- 合并语义: 同一主机全部来源都确认才允许 h3, 任一否认即否决.
- 主机按后缀最长匹配, verdict 作用于该主机及其子域.
- 无数据时回退调用方默认 (一般站点保留上游 ALPN, X 与 Meta 固定 h2).
- 有效快照变化递增代数; 代数折入 HTTPS 应答缓存键, 翻转即刻生效.
- verdict 来源表可序列化为探针态快照; 代数不入快照, 重启后从当前快照重新起算 (换代只会穿透旧缓存, 方向安全).

对外接口:

```go
type Verdict struct { Host string; Allowed bool; Sources []string }
type StatusReport struct { Effective map[string]bool; Sources []SourceStatus }
func SetVerdicts(source string, verdicts map[string]bool, ttl int)
func VerdictFor(name string) *Verdict
func AlpnFor(name string, fallback []string) (alpn []string, why string)
func CacheTag() string
func Status() *StatusReport
func SaveState(path string) error
func LoadState(path string) error
```

数据所有权: verdict 来源表; 当前代数.

扩展规则:
- 全票制语义固定, 变更须经 PRD.
- 代数只增不减; 缓存标签格式稳定 (h3g 前缀加数字).
- 快照文件不存在视为无状态, 内容损坏记日志后保持空态, 不阻塞启动; 格式变更须带版本号.

事件目录:
- h3_verdicts_updated — verdict 报告覆盖; detail: source, verdict 数, ttl.
