# Agent Note: CF 改写门控在有可用优选池时自动提升

Status: implemented
Scope: internal/resolver/resolver.go, internal/rewrite/rewrite.go

## Problem

PRD F-009 写 "改写启用条件: 存在任一可用池", 但配置项 CF_REWRITE_ENABLED 是全局布尔. 若 RewriteAddresses 只看全局开关, 显式 ?ip4/?cf= 参数与学习池在开关关闭时全部失效, 与 F-017 验收 ("?ip4=a,b → A 记录为指定地址") 矛盾; 若只看池存在, 全局开关形同虚设.

## Decision

resolver 在 prepareFull 取池成功后, 经 rewriteCfg(cfg, plan.pool) 派生请求级配置副本: 池非空 (v4 或 v6 有地址) 时把副本的 CFRewriteEnabled 置真, 原始 cfg 不变. 改写链整链使用该副本, 与 refer prepareDns 的 `cfRewriteEnabled: config.cfRewriteEnabled || preferred.ipv4.length > 0 || preferred.ipv6.length > 0` 语义逐字对齐.

## Alternatives considered

- 只看池存在, 删掉全局开关: 输给配置语义 — CF_REWRITE_ENABLED 是行为基线的部署开关, 需保留.
- 在 RewriteAddresses 内部判断池非空即放行: 输给所有权 — 池的解析住 resolver, rewrite 只消费传入的 pool; 在下游推断上游状态会把门控逻辑分散到两处.

## Consequences

- 全局开关关闭 + 无任何池 → 不改写 (原样应答); 同配置下探针/公开池一旦供给地址, 改写自动生效, 无需改配置.
- 代价: 每请求一次 config 结构体副本 (仅在有池且开关关闭时), 可忽略.
