# Agent Note: cfhost 可携式布局: 配置状态锁日志全跟随配置目录

Status: implemented
Scope: internal/cfhost/config.go, deploy/cfhost.service, .trellis/spec/arch/cfhost.md

## Problem

cfhost 的配置, 状态, 锁与日志默认散落两处: 配置与状态在 UserConfigDir (Windows 为 %APPDATA%\cfdoh\), 程序在别处. 菜包的部署习惯是绿色式 — 可执行文件与配置文件放同一目录, 升级/备份/迁移整个文件夹拿走. 需要决定默认布局调整到什么程度: 只挪配置, 还是全部运行时产物跟随.

## Decision

2026-10-04 菜包拍板全套跟随: 默认配置 = 可执行文件同目录的 cfhost.json; 状态 (cfhost-state.json), 单实例锁 (cfhost.lock) 与日志 (cfhost.log) 默认落在配置文件所在目录 (exe 路径不可得时配置回退 UserConfigDir). 显式 CFHOST_CONFIG=D:\x\cfhost.json 时状态默认也落 D:\x\; CFHOST_STATE_PATH 仍可单独覆盖状态, 锁与日志随状态目录. 一个文件夹装下全部运行时产物, 无隐藏的散落文件.

## Alternatives considered

- 只挪配置文件, 状态/日志留在 UserConfigDir: 输给全套跟随 — 同样是用户可观察路径, 留一半散落 (状态写 %APPDATA%) 违背 "统一目录" 的初衷, 且两处默认规则更难解释.
- 跟随工作目录 (cwd) 而非 exe 目录: 输给 exe 目录 — Windows 服务与手动启动的 cwd 不稳定 (服务默认 System32), exe 目录是唯一确定性锚点.

## Consequences

- 老部署升级后默认位置读不到旧配置与旧状态: 需复制 cfhost.json 到 exe 目录 (或设 CFHOST_CONFIG), 状态丢失仅触发一轮重新测速. 属可观察行为变化, 下次 release 走 minor (v1.1.0) 而非 patch.
- systemd 单元因显式 CFHOST_CONFIG=/etc/cfdoh/, 新语义会把状态写进 /etc — 已同步钉 CFHOST_STATE_PATH=/var/lib/cfdoh/.
- Go 单测两条钉死: 默认配置 = exe 目录; 状态/锁/日志目录 = 配置目录. 验收套件全程显式路径, 不受默认值影响.
