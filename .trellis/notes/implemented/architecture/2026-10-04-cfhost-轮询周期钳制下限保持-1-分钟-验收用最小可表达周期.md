# Agent Note: cfhost 轮询周期钳制下限保持 1 分钟, 验收用最小可表达周期

Status: implemented
Scope: internal/cfhost/config.go, test/acceptance/test_f026_runloop.py, .trellis/spec/arch/cfhost.md

## Problem

验收套件 testplan (10-04-acceptance-py) 的周期轮询用例最初假设 INTERVAL=3s 可配. 实际上 cfhost 周期的唯一配置通道 CFHOST_INTERVAL_MIN 是分钟整数, 且实现将周期钳至下限 1 分钟 (internal/cfhost/config.go 的 minInterval). spec (arch/cfhost.md) 未定义任何钳制区间, 该下限是实现自引入 — 用例按 3s 周期断言必然红. 需要裁决: 改产品还是改验收参数.

## Decision

验收侧修订 (2026-10-04 菜包拍板方案 B): test_f026_runloop_periodic 用最小可表达周期 CFHOST_INTERVAL_MIN=1 (即 1 分钟), 观测窗口 ~130s, 断言窗口内源拉取计数 ≥2 且状态文件 next_run 推进. 产品钳制下限 1 分钟保持不变; 用例的用户可观察语义 (证明自动周期轮询存在) 完整保留. cfhost 钳制区间补入 spec 登记为后续任务, 不在验收任务内改产品.

## Alternatives considered

- 方案 A (改产品开放亚分钟周期): 输给 B. 1 分钟下限是合理的水源礼貌性设计 (避免终端用户以秒级频率轮询候选源); 仅为可测性翻转产品行为是本末倒置, 且 spec 从未承诺亚分钟周期, 3s 是规划期假设.

## Consequences

- 已落地: test_f026_runloop_periodic 以 CFHOST_INTERVAL_MIN=1 运行, 130s 窗口内受控源新增拉取 ≥2 且 next_run 推进, 全量 acceptance 127 例绿 (批 5 提交 907bb33); testplan 用例行与已知取舍 #7 已记录裁决.
- internal/cfhost/config.go 的 minInterval 与 CFHOST_INTERVAL_MIN 分钟语义不变; 未改产品.
- 套件耗时 +~2 分钟 (窗口 130s), 全量实测 ~375s.
- 钳制区间已补入 spec: c0c3bb6 起 cfhost.md 环境变量与钳制区间表 (含 CFHOST_INTERVAL_MIN 钳 1min–24h) 为唯一真源, 本条原登记的 “补 spec 前窗口” 已闭合; 未来调 minInterval 或改通道粒度属 spec 变更, 须同步改表与用例.
